# Defer Threaded Conversation Model

Phase 1A should not add a formal Tendnote conversation thread or assistant event model unless reloadable chat becomes necessary for the first review loop. Eve sessions already provide durable conversations, continuation tokens, and default context-window compaction, so Phase 1A can rely on Eve for short-term session continuity while Tendnote product state remains in source records, memories, follow-ups, briefs, drafts, and audit logs.

Later follow-up and drafting phases should add Tendnote-owned conversation threads if users need ChatGPT- or Claude-style resumable conversations. Those threads should reference Eve session ids and persisted product records, but they should still not make chat transcripts the source of truth for relationship memory or approvals.
