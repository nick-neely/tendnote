# Relationship Agenda Is A Read Model

Phase 1E.25 should implement the relationship agenda as a shared owner-scoped read model over existing records, not as a mutation surface or suggestion generator. `get_relationship_agenda` should combine deterministic records with Phase 1D semantic retrieval matches, ranking persisted follow-ups, birthdays, review items, recent eligible context, and fuzzy relationship context while failing open when embeddings are missing or stale. It must not create follow-ups, create suggested follow-ups, update prompting metadata, run a background scanner, or persist brief artifacts. Eve can still create or suggest follow-ups through the existing explicit follow-up tools after the user expresses that intent; keeping those actions outside the agenda tool prevents broad "what is coming up?" questions from quietly becoming task creation.
