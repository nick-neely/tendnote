# Relational Retrieval Before Full-Text

Phase 1A should use plain Postgres relational retrieval before adding full-text search. Initial retrieval should be scoped and inspectable through fields such as `owner_user_id`, `person_id`, `status`, `source_type`, `due_at`, `created_at`, and internal `importance`.

Postgres full-text search should remain a distinct Phase 1C slice after the product can already store source records, promote suggested memories, build context snapshots, and route web chat through Eve. Phase 1C intentionally comes before follow-ups, briefs, and drafting so exact recall can improve the assistant and shared retrieval layer before proactive action surfaces depend on it.

This keeps full-text search behind the proven capture, review, and snapshot loop while bringing exact recall forward once Eve has a real conversational surface. Follow-ups, briefs, and drafting should consume this shared retrieval capability later rather than each inventing its own search behavior.

Phase 1C should expose full-text search through a shared owner-scoped retrieval entry point, primarily for Eve and other product code. Normal recall should search canonical records such as people, approved memories, and active source records, returning typed record references rather than generated snapshot prose. Suggested memories should stay out of normal recall because they are review items, not relationship facts; a later review-mode search may include them only when the result contract clearly labels them as tentative. Restricted content should be excluded by default and only returned through an explicit directly requested path, matching the broader context policy. The result shape should leave room for later pgvector semantic retrieval to contribute separate fuzzy matches without treating exact full-text search and semantic retrieval as the same concept.

Eve should receive this capability through a distinct `search_relationship_context` tool backed by the shared query. `search_people` remains identity lookup and disambiguation, while `get_person_context` remains the known-person context loader. Keeping exact recall separate prevents person lookup, profile loading, and relationship search from becoming one overloaded tool contract.

Search results should be compact typed references, not full context packs. Each result should identify the record kind, record id, related person id and display name when available, a short label or snippet, matched fields, rank, trust level, and sensitivity. Eve can use those results to decide whether to call `get_person_context` for richer known-person context; full-text search should find relevant records, not assemble complete profiles.

The database implementation should use durable per-table Postgres full-text indexes, such as stored/generated `tsvector` columns or equivalent stable migration SQL with GIN indexes, rather than a denormalized search table in Phase 1C. The shared search query can combine ranked table-specific searches with `UNION ALL`, preserving each canonical table as the source of truth while leaving room to tune weights and add semantic retrieval later.

The initial search contract should stay small: query text, optional person id, optional record-kind filter, limit, and an explicit directly requested flag for restricted content. Phase 1C should avoid broader reporting-style filters such as date ranges, relationship type, source type, or memory type until a concrete product surface needs them.

Phase 1C UI should stay minimal. The required product surface is Eve's ability to render compact `search_relationship_context` results and route the user toward existing person, source-record, or review surfaces. A full global search page should wait until search has enough usage to justify a dedicated surface.

Phase 1C completion should be proven mostly with deterministic query, policy, tool, rendering, and migration tests. Coverage should include owner scoping, result-kind filters, person filters, ranking, limits, lifecycle exclusions, suggested-memory exclusion from normal recall, restricted-content exclusion by default, explicit restricted retrieval, Eve's use of the shared query, compact typed result rendering, and the full-text migration/index shape. Model evals should wait until search output is used for generation quality decisions.

Ranking should stay deterministic and exact-recall oriented. PostgreSQL text rank should be the base signal, with small table-specific weights where useful and recency or importance used only as light boosts or tie-breakers. Phase 1C should not introduce personalized recommendation ranking or let importance and recency overpower direct text matches.
