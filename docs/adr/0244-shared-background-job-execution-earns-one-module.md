# Shared Background-Job Execution Earns One Module

Suggested Memory extraction, General Action extraction, and semantic embedding are three Postgres-owned job families that had each re-inlined the same execution mechanics across the web and Eve runtimes: runtime-mode resolution, outbox delivery creation, queue publication, claim interpretation (duplicate/stale/replayed/missing/terminal/not-claimable), terminal behavior, rate-limit deferral, and recovery backfill. The deletion test — "if we removed the shared piece, would these mechanics have to be spread back across every family and runtime?" — comes back yes, so the mechanics earn a single module: `@tendnote/db/queries/background-jobs`. It concentrates the family registry, the generic `enqueueAndPublishBackgroundJob` path, and the shared claim-translation processor builder; the web keeps only the rate-limit-aware consumer loop and each app injects its own Vercel queue transport adapter.

What stays per-family is each processor's domain implementation and its own status/outcome enums: memory extraction keeps grounding, trust, scope, retries, audits, and Suggested Memory outcomes; General Action extraction keeps review gating, source grounding, deduplication, restricted-content policy, and embedding scheduling; semantic embedding keeps record-kind behavior, owner scope, eligibility, idempotency, and retrieval trust. The shared module never reaches into those decisions — it only drives the family's `claimJob` / `getJob` / `processJob` / `claimNextJob` and enqueue-and-trigger seams.

The registry is a closed, exhaustive enumeration keyed by `BackgroundJobKind`, not a generic event bus: a compile-time completeness guard plus a runtime completeness test make adding another Postgres-owned job family an explicit, type-enforced registration rather than a dynamic subscription. Postgres remains authoritative for job state, retry timing, outcomes, and idempotent claims; the queue only carries pointers, and recovery reuses the shared mechanics without becoming the normal production processing loop.
