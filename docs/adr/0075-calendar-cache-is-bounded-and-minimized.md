# Calendar Cache Is Bounded And Minimized

Phase 2C should add a short-lived, minimized Calendar read cache rather than choosing between live-only reads and a full provider sync database. Live Google Calendar remains the source of truth, Better Auth owns OAuth token custody, Provider Connections own product consent/status, and the cache stores only normalized event summaries needed for Eve grounding, previews, scheduled brief generation, and near-term product workflows. The cache should be keyed by owner, connection, calendar id, and bounded window/query shape, expire aggressively, avoid raw provider payload storage, and stay reusable by the existing app-owned brief dispatcher or later Eve schedules without becoming approved memory, retained source records, or a broad ingestion subsystem. Phase 2C should let scheduled workflows refresh/read through this seam when generating their own artifacts, but should not add a standalone Calendar background sync loop before a concrete workflow needs it.
