# Instant Navigation Gates Are Tiered By Signal And Cost

Tendnote will enforce Instant Interaction with a small production-build browser matrix while keeping environment-sensitive performance measurements separate from deterministic correctness gates. Every admitted critical navigation must immediately show a truthful, layout-stable destination shell; streamed content, owner isolation, cache correctness, hydration, and optimistic reconciliation must then reach authoritative state. Chromium owns routine `instant()` coverage and measurements. Firefox and WebKit retain reduced upgrade-and-promotion smoke coverage rather than adding a three-browser tax to every application pull request.

The routine Chromium matrix covers desktop Today to People, People to person detail, person detail to Today, mobile Today to Review, mobile Menu to Actions, and mobile People to person detail. A seeded Action complete-and-reopen scenario runs on desktop and mobile. If three cache-warm CI runs show that this parallel job does not finish beneath the existing Test and Fallow critical path, routine PR coverage contracts to desktop Today to People, mobile Today to Review, and Action complete-and-reopen; the full matrix remains mandatory for the framework upgrade and production promotion.

Hard gates are the 100 millisecond Instant Interaction contract, cumulative layout shift no greater than `0.01`, truthful streamed completion, authoritative reconciliation, and privacy/cache isolation. Upgrade acceptance additionally requires at least a 20 percent median completion-time improvement for Today and person detail, no greater than a 10 percent regression on any other measured critical transition, no cold-JavaScript growth for Today, Review, or person detail, optimistic acknowledgement within 100 milliseconds, and authoritative seeded-Action reconciliation within 500 milliseconds. Query time, RSC and client payloads, request fan-out, and server work remain recorded diagnostics until repeatable post-upgrade distributions justify stable regression gates.

The browser job runs in parallel rather than extending the existing serial test job. Three cache-warm application runs must keep the aggregate `Verify` wall time below nine minutes; a clean run reaching ten minutes fails the rollout criterion. Before adding runner cost or weakening existing coverage, implementation must first reuse browser installs, seed fixtures efficiently, and remove redundant setup.

Performance fixtures contain only deterministic synthetic data: one primary fake owner with representative records plus a second fake owner used to prove isolation. Time and identifiers are stable, record counts are bounded, cold and warm measurements are separate, and no production data, live provider credentials, Eve model calls, or external network dependencies participate. Each mutation scenario begins from known state and restores it through authoritative product commands.
