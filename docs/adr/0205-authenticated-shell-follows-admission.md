# Authenticated Shell Follows Admission

Tendnote will render only a neutral branded access-check fallback until request-bound Better Auth and Private Beta Access resolve; unauthenticated callers redirect to sign-in, pending callers redirect to the pending area, and hosted failures remain closed. After admission, an owner-neutral desktop and mobile frame may prerender or prefetch immediately, with useful route-specific fallbacks while owner data streams. This gives admitted navigation an instant, recognizable destination without flashing private-product chrome to callers who have not passed the access boundary.

The current client `AppShell` will split into server-rendered layout and navigation plus narrow client islands for mobile focused flows, online state, PWA and reminder effects, Search, and Capture. Today and Eve remain route-owned rather than shared-shell data. The verified `ownerUserId` is passed explicitly into owner-scoped cached reads and local draft keys, but serialized identity is never authority: cache keys and tags include the owner, sessions and admission decisions are never shared-cached, and every server action resolves the admitted caller again before reading or mutating data.
